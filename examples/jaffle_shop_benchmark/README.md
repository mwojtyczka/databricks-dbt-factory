# jaffle-shop model reuse benchmark

Measures what model reuse saves on a real dbt project. Both arms run the same jaffle-shop project on
serverless Databricks compute through the same notebook runner. The **off** arm has no reuse. The **on**
arm enables reuse project-wide, with `+meta: {dbt_factory: {reuse: {enabled: true}}}` in `dbt_project.yml`.

- Project: [dbt-labs/jaffle-shop](https://github.com/dbt-labs/jaffle-shop) at commit
  `0f25768470271be01c2663f1c53f366b53d41823`, fetched by `bench.py` (not vendored). This is the last commit
  whose `dbt_project.yml` requires dbt >=1.12. The current HEAD requires dbt v2 and does not parse on the
  dbt-core 1.12 pin used by the serverless environment.
- Raw sources: generated by a Spark task (`bundle/generate_data.py`) with the jaffle-shop column names, in
  `jaffle_bench_raw`. Scale factor `SF` sets the order count (`SF * 1,000,000`). The default `SF=0.001` is
  a smoke size. A full-run size is not calibrated yet.
- Compute: one bundle-owned serverless SQL warehouse, 2X-Small, auto-stop 5 minutes.

## Run

```shell
make bench SF=0.001 REPS=1       # whole benchmark; appends rows to test_jg_catalog.jaffle_bench_results
make bench-clean                  # destroy the bundle and drop jaffle_bench_raw/off/on (results are kept)
```

Requires `uv`, `git`, and the Databricks CLI with the `fevm-test-jg` profile. `make bench` runs
`bench.py run`. On failure it cancels its runs and cleans up, unless `python bench.py run --keep` is used.

What one run does:

1. Deploys the warehouse, then the control job (`bundle/control.yml`) and the project.
2. Captures reuse provenance inside a serverless job (`capture_parse`). The context fingerprints the runtime
   packages, so capture must run there, not on the laptop. Two variants are captured: `base` (the pinned
   project) and `edit` (`stg_supplies.sql` gains `where supply_id is not null`: its compiled SQL and view
   definition change, its rows do not, so `supplies`, `order_items`, `orders` and `customers` rebuild).
3. Generates the arm jobs with the Factory CLI, one with `--reuse-config`/`--reuse-provenance` for the on arm,
   and publishes the immutable reuse artifacts to the `jaffle_bench_on.artifacts` volume.
4. Runs the plan from `bench.py plan()`: for each arm, reset the raw data and arm schema, then `cold`,
   `rerun`, append ~1% of orders and items, `append`, switch to the `edit` variant, and `edit`. Each
   rep alternates arm order.

Schemas: `jaffle_bench_raw` (sources), `jaffle_bench_off` and `jaffle_bench_on` (one per arm; reuse state and
the artifact volume live in `on`), `jaffle_bench_results` (persistent). Targets are `arm_off` and `arm_on`
(YAML reads bare `on`/`off` as booleans).

## Results

Each job task becomes one row in `test_jg_catalog.jaffle_bench_results.reuse_benchmark_runs`. Control steps
(reset, append) are rows with `step_kind` `reset` or `append`. The table records the factory and jaffle-shop
SHAs, scale factor, task seconds, run seconds, dbt run and test invocations and the reuse reason.
`bundle/benchmark_results.py` summarizes off vs on per scenario, overhead and history, and attributes
warehouse time (`system.query.history`) and serverless job DBUs (`system.billing.usage`) to each arm job run
when it runs. Query history lags minutes and billing hours, so rerun the notebook later for complete rows. `RESULTS.md` holds
the latest headline numbers.

## Notes

- The sync (`sync.include` in `bundle/databricks.yml`) is needed because the repo `.gitignore` ignores `build/`.
- Reuse runtime skipping is still gated by `REUSE_ENABLED` in `src/`. The on arm sets it per run through the
  harness runner (`tests/databricks/acceptance_runner.py`, copied into the bundle). Production stays `False`.
- Cost: serverless SQL warehouse time dominates. Measure with `system.billing.usage` after the run.
